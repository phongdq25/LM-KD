# Troubleshooting & Frequently Asked Questions (FAQ)

This guide addresses common errors, performance bottlenecks, and pitfalls encountered when training and evaluating distillation setups in LM-KD.

---

## 1. CUDA Out-Of-Memory (OOM) Errors

### Symptom: OOM During Loss Computation
```text
torch.cuda.OutOfMemoryError: CUDA out of memory. Tried to allocate 4.60 GiB
(GPU 0; 79.15 GiB total capacity; 72.10 GiB already allocated)
```

### Cause
Modern LLMs feature large vocabularies (e.g., $V = 152,064$ for Qwen2.5/Qwen3, $V = 128,256$ for Llama-3). Storing raw floating-point logits for both student and teacher across a batch $[B, S, V]$ consumes:
$$\text{Memory} = 2 \times B \times S \times V \times 2\text{ bytes (BF16)}$$
For $B = 4$, $S = 4096$, $V = 152064$:
$$\text{Memory} \approx 2 \times 4 \times 4096 \times 152064 \times 2 \approx 9.96\text{ GB per step}$$
Computing `log_softmax` over this tensor immediately triggers an out-of-memory exception.

### Solutions
1. **Enable Lazy Logit Chunking:**
   LM-KD includes an automatic target-aligned chunked divergence engine ([`src/lmkd/models/logits_view.py`](../../src/lmkd/models/logits_view.py) and [`src/lmkd/models/chunked_head.py`](../../src/lmkd/models/chunked_head.py)) that computes divergences over sequence chunks without materializing full $[B, S, V]$ tensors:
   ```yaml
   loss:
     terms:
       - criterion: token_kd
         params:
           divergence: fkl
           chunk_size: 512  # Compute KL across 512-token sequence slices
   ```
2. **Use Top-$K$ Logit Distillation:**
   Instead of the full vocabulary, transfer only the top $K$ candidate tokens from the teacher:
   ```yaml
   loss:
     terms:
       - criterion: token_kd
         params:
           divergence: fkl
           top_k: 256  # Only transfer teacher's top 256 logits
   ```
3. **DeepSpeed ZeRO-3 Offload for Teacher:**
   Keep the teacher model in CPU memory or partitioned across ranks:
   ```yaml
   _base_:
     - recipes/_base_/engine_zero3.yaml
   ```

## 2. Tokenizer Mismatches in Cross-Tokenizer Distillation

### Symptom: Dimension Mismatch or Semantic Drift
```text
ValueError: Vocabulary size mismatch: Student has 32,000 tokens while Teacher has 151,936 tokens.
```

### Cause
Direct logit distillation ($\mathcal{L}_{\text{KD}}(P_T, P_S)$) mathematically assumes that student and teacher share identical vocabulary tokens $V_T \equiv V_S$. When distilling across different model families (e.g., Qwen $\rightarrow$ Llama or Mistral $\rightarrow$ OPT), token identities and token boundaries do not align.

### Solutions
1. **Use Cross-Tokenizer Criteria:**
   Do not use standard `fkl` or `rkl` for cross-family distillation. Instead, use cross-tokenizer methods from `recipes/cross_tokenizer/`:
   - `dskdv2` (Dual-Space Knowledge Distillation with soft token mapping)
   - `impact` (Information-Maximizing Partitioned Alignment)
   - `mcw_kd` (Multi-Cost Wasserstein KD)
   - `sra` (Span Representation Alignment)
2. **Configure an Aligner:**
   Add a token aligner transform under `data.transforms`:
   ```yaml
   data:
     transforms:
       - type: align
         aligner:
           type: dtw_edit  # Dynamic Time Warping based on subword edit distance
           similarity_threshold: 0.8
   ```

## 3. Padding and Loss Masking Pitfalls

### Symptom: Distillation Loss Stagnates or Explodes
During training, the loss does not decrease, or the student generates repetitive padding tokens during evaluation.

### Cause
- **Left vs. Right Padding:** Generation runtimes (such as vLLM) require **left-padding** for batched autoregressive generation, whereas causal cross-entropy distillation requires **right-padding** with appropriate loss masks.
- **Unmasked Prompt Tokens:** In instruction distillation, distilling the prompt tokens forces the student to memorize the prompt distribution rather than learning to generate the response conditioned on the prompt.

### Solutions
- Ensure instruction tokenization properly masks prompt tokens:
  ```yaml
  data:
    transforms:
      - type: tokenize_sft
        use_chat_template: true
    padding: dynamic
  ```
- LM-KD automatically normalizes losses by `num_items_in_batch` (the exact count of valid response tokens in the global batch) to prevent gradient shrinkage or explosion across variable-length sequences.

## 4. vLLM and Distributed Training Co-location Conflicts

### Symptom: Ray / vLLM Crashes with Out of Memory on Engine Init
```text
RuntimeError: Engine failed to initialize because GPU memory is exhausted by PyTorch.
```

### Cause
When running on-policy distillation (e.g., GKD, OPSD, SPIN), student rollouts are generated by vLLM while student gradients are accumulated by PyTorch/DeepSpeed on the same GPU. If PyTorch pre-allocates the CUDA memory pool, vLLM cannot allocate its KV-cache.

### Solutions
1. **Limit vLLM GPU Utilization:**
   Configure vLLM to reserve memory for PyTorch:
   ```yaml
   rollout:
     type: vllm_colocate
     gpu_memory_utilization: 0.35  # Allocate 35% to vLLM KV-cache, 65% to PyTorch
   ```
2. **Decoupled Architecture:**
   For multi-GPU clusters, run vLLM on dedicated rollout GPUs and stream rollout sequences over IPC:
   ```yaml
   rollout:
     type: vllm_server
     host: "127.0.0.1"
     port: 8000
   ```

## 5. Numerical Instability in Reverse KL & Surrogate Divergences

### Symptom: `NaN` or `Inf` Losses During On-Policy Distillation
```text
[Step 142] Loss: nan | Student Grad Norm: inf
```

### Cause
Reverse KL $\mathcal{L}_{\text{RKL}} = \sum P_S \log \frac{P_S}{P_T}$ evaluates teacher probabilities $P_T$ on tokens sampled from the student policy $P_S$. When the student explores rare or ungrammatical sequences, $P_T(y) \to 0$, causing $\log P_T(y) \to -\infty$.

### Solutions
1. **Apply Surrogate Truncation (CSD):**
   Use surrogate clipped objectives that bound the importance ratio:
   ```yaml
   loss:
     terms:
       - criterion: token_kd
         params:
           divergence: csd
           clip_ratio: 5.0
           temperature: 1.0
   ```
2. **Gradient Clipping & BF16 Mixed Precision:**
   Ensure gradient clipping is set in the configuration:
   ```yaml
   grad:
     clip_norm: 1.0
   ```
