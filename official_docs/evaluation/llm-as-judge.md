# Automated LLM-as-a-Judge Evaluation

For open-ended conversational tasks (such as AlpacaEval, MT-Bench, and Vicuna Evaluation), automated evaluation by frontier judge models provides high correlation ($> 0.9$) with human preference rankings.

However, uncalibrated judges suffer from systematic biases. LM-KD implements automated debiasing protocols to ensure objective assessments.

---

## 1. Automated Debiasing Protocols

### 1. Position Bias Correction (Bidirectional Swap)
LLM judges exhibit a strong tendency to favor whichever response appears first in the prompt ("Position A bias"). LM-KD enforces a **two-pass evaluation**:
1. **Pass 1:** Prompt contains `Response A = Student`, `Response B = Baseline`.
2. **Pass 2:** Prompt swapped: `Response A = Baseline`, `Response B = Student`.
3. **Scoring:** The student receives a win if and only if it is chosen in *both* passes. If the judge flips its decision based on position, the matchup is scored as a **tie**.

### 2. Verbosity & Length Bias Control
Students distilled with high temperatures or unregularized SFT often generate verbose, repetitive responses that fool naive judges into awarding higher marks.
- The evaluation harness includes an explicit length penalty prompt instruction.
- The reporting dashboard logs the **Win-Rate vs. Token-Length Correlation** to verify that gains do not stem from verbosity exploitation.

### 3. Self-Enhancement Bias Mitigation
Models tend to score outputs generated by their own model family higher. When evaluating Qwen-based students, LM-KD defaults to an impartial third-party judge (e.g., Claude 3.5 Sonnet or GPT-4o) rather than a Qwen teacher.

---

## 2. Pairwise Judge Evaluation Protocol

For standardized benchmarks like AlpacaEval or MT-Bench, first export student model generations using `lmkd eval`:

```bash
# Generate evaluation completions using the standard evaluator
lmkd eval -c recipes/same_tokenizer/fkl.yaml --ckpt outputs/fkl/checkpoint-final
```

Completions are written to `outputs/<experiment>/eval/generation_rouge/raw.jsonl`. Pairwise win-rate evaluation against a baseline (e.g. standard SFT) using an external judge model (such as GPT-4o) can then be run via AlpacaEval or a custom evaluation script adhering to the debiasing protocol:

```bash
# Example pairwise evaluation run with bidirectional swap
python -m lmkd.eval.benchmarks \
    --candidate outputs/fkl/checkpoint-final \
    --baseline outputs/sft/checkpoint-final \
    --benchmark alpaca_eval \
    --judge gpt-4o \
    --bidirectional \
    --output_report outputs/judge_results.json
```
